Scope · what we build

  • Minimal POST /mcp/v1/rpc Plug endpoint speaking JSON-RPC 2.0. Handles initialize, tools/list, tools/call. Bearer-token auth via existing MCPAuth plug.
  • One tool: narrate. Tool definition derived from a hardcoded list (catalog wiring is a path-B-proper task, not a spike-task).
  • Worker: extend test_hub_agent.py with one test that builds MCPToolset(url=http://localhost:4000/mcp/v1/rpc), instantiates HubAgent with it, drives one turn.
  • Elixir-side: log the inbound JSON-RPC call so we can prove it landed. No FSM transitions, no Session writes.
Budget: 1 working day (~6 hrs). Scope-creep guard: if you find yourself wiring real tool dispatch, stop — that's path B proper.

Success · what proves it

  • Worker spawns. MCPToolset connects to the Elixir endpoint without protocol error.
  • The cascaded session, prompted to "say hello using narrate", invokes the tool. We see the tools/call arrive Elixir-side in logs.
  • The Elixir handler responds with a synthetic result; the worker LLM receives it and the next turn references it (proving the round-trip closes).
  • One new Elixir test + one new Python test, both green. Suite stays at 1349+ / 0.
If all four hold: path B is GO; cut the goal file. If only 1-2 hold: capture the gap and decide whether to fix in path B scope or escalate.

Kill · what makes us pivot

  • Streamable-HTTP handshake from LiveKit MCPServerHTTP doesn't complete in 2 hrs of debug time. Pivot: investigate FastAPI sidecar that proxies HTTP→BEAM via Erlang Distribution / native messaging.
  • LiveKit MCP transport version we implement is incompatible with the JS SDK's. Pivot: pin the exact spec version + re-cut the spike against it.
  • Bearer-auth pattern doesn't survive the LiveKit dispatch flow (workers expect a token that we control). Pivot: design a token-mint endpoint inside the spike.
  • Cost / latency of the round-trip blows the voice-budget (>200ms p50 for a local tool call). Pivot: investigate Phoenix.Channels-over-LiveKit-DataChannels instead of HTTP RPC.
Any kill triggers a re-plan thread — the spike yields signal either way.
