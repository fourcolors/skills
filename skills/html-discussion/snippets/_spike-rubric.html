R8
Session lifecycle: stateless vs server-side state?
Big design implication for Phase 1.
 PASS = we know definitively from spec + traffic. mcp/server/streamable_http.py:48-51 + FastMCP stateless_http=True setting PARTIAL Protocol supports both via the mcp-session-id response header. Server can set mcp_session_id=None for stateless OR generate per-connection IDs for stateful. Spike Plug is fully stateless (no session header emitted). Phase 1 decides: if MCP server needs per-call_id state (e.g., tracking which Session GenServer to dispatch to), stateful makes sense — session-id can mirror call_id. Stateless is simpler and viable for spike validation; not load-bearing for the verdict.
